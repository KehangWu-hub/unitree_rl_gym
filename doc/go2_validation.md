# Go2 验证与技术说明

本文说明项目结果的适用范围和训练、部署之间需要保持一致的接口。日常运行步骤见[真机部署指南](../deploy/deploy_real/README_GO2.zh.md)。

## 验证范围

| 环境 | 已完成工作 | 适用边界 |
|---|---|---|
| Isaac Gym | 1500轮正式训练，45/60维Actor-Critic，Play与策略导出 | 训练及仿真结果 |
| 策略接口 | checkpoint Actor与TorchScript随机输入对照，关节映射与观测布局检查 | 不等于实体执行效果 |
| Python MuJoCo | 方向、组合指令、长时与外力扰动测试 | 存在速度欠跟踪及物理模型差异 |
| DDS / MuJoCo | 控制闭环、键盘、看门狗及故障停止检查 | 软件通信链路与仿真范围 |
| 实体 Go2 EDU | 有线只读、影子推理、站姿接管、零速、短时运动与收尾 | 有现场观察，实际速度和距离未独立测量 |

真机短时运动覆盖前进、后退、左右侧移及行进中左右转向。当前14/16Nm参数下有前进加转向、后退及左右侧移记录；纯W前进0.40m/s的记录来自此前参数，尚未在当前参数下单独复测。Q/E使用前进加转向，不代表原地转向通过。

最新左右侧移均得到连续迈步、已卧倒停住且无异常的现场确认。右移记录有X主动归零转换；左移记录由预算耗尽归零，不能将较晚的X输入记为主动停走测试。

尚未完成的工作包括长时真机运行、实际速度与距离测量、原地转向、跨起始状态的侧移重复可靠性，以及完整断链或电脑断电后的停机验证。

## 训练与部署接口

Actor观测按以下顺序构造，共45维：

| 观测 | 维度 | 缩放 |
|---|---|---|
| 机身角速度 | 3 | 0.25 |
| 投影重力 | 3 | 1.0 |
| 前进、侧向、偏航指令 | 3 | 2.0 / 2.0 / 0.25 |
| 关节位置相对默认角度 | 12 | 1.0 |
| 关节速度 | 12 | 0.05 |
| 上一策略动作 | 12 | 1.0 |

Actor不使用基座线速度。Critic在训练时额外使用仿真线速度与关节力矩，输入为60维，不进入导出的推理模型。

策略关节顺序为FL/FR/RL/RR，SDK顺序为FR/FL/RR/RL；每条腿依次为hip、thigh、calf。名称映射由共用接口维护。

```text
关节参考目标 = 默认关节角 + 0.25 × 策略动作
```

策略周期20ms，部署使用Kp20/Kd0.5。修改观测、缩放、关节映射、默认角度、动作缩放、增益或周期后，应重新执行对应仿真和部署检查。策略与导出参数必须配套，冻结模型与当前真机配置的摘要保存在[基线清单](../deploy/deploy_real/configs/go2_verified_baseline.json)。

## 目标与力矩处理

真机调试曾发现参考目标越过小腿模型上限，以及额外10.5Nm限幅持续削弱部分小腿PD输出。部署改为先限制参考目标到模型范围，并在既定短时测试后采用14Nm PD限幅与16Nm反馈停止阈值。

参考目标越界与实际关节越界是不同情况。原始策略动作仍保留为`last_action`，实际关节、动作幅值与变化、姿态、通信和力矩保护独立执行。前后大腿模型限位不同，当前配置与URDF/MJCF逐项对应。

后退与侧移的降低末态跟踪门槛为0.25rad，原前进/转向末态为0.15rad。门槛调整没有改善实际跟踪精度；不能将接受判据的变化解释为物理效果改善。

14/16Nm属于本项目短时参数，不是原厂推荐值，也没有构成长时或全运动范围的保证。

## 侧移停滞

早期两轮左移指令生效，但现场几乎未移动。离线策略回放与历史输出一致，未发生参考或PD裁剪，也未提前触发保护。末秒策略目标逐渐固定，实际关节最大变化约0.0017rad，表明闭环趋于静态。

后续保留同一冻结模型和控制参数，用户在现场交互终端完成左右侧移，观察到连续迈步。成功左移末秒实际关节变化约0.037～0.187rad，右移约0.030～0.168rad，目标和关节持续变化。

从真实停滞状态启动的MuJoCo对照，在部分接触条件下可复现停滞，但接触维度、关节阻力和约1mm初始高度差均可能改变结果。现有证据支持状态与接触条件相关的闭环停滞，尚不能确定唯一真实触发因素，也不能用仿真假设辨识瓷砖摩擦或直接选择真机增益。

新增日志保留足端原始字段和IMU加速度，用于后续对照。足端字段未核对单位、足序和校准，不能直接当作牛顿或精确接触力；本轮`foot_force_est`全零。[官方LowState读取示例](https://github.com/unitreerobotics/unitree_ros2/blob/master/example/src/src/read_low_state.cpp)也将足端字段作为整数原始值展示。

## 如何解读检查结果

- **流程通过**：指令、时序、保护和退出符合预期。
- **方向通过**：位移方向符合指令。
- **运动效果**：实际运动幅值、持续迈步与停止需单独评价。

早期MuJoCo检查仅要求方向位移大于1cm，不能用来说明速度跟踪良好。当前受限键盘仿真报告增加运动窗口实际/指令距离比，默认门槛0.5是工程判据，不是原厂标准。

只读、影子推理和离线回放不下发电机命令。日志分析器的通过结果也不会自动确认实体运动；现场观察及独立测量应与软件结果分别记录。

## 数据与复核

训练产物、JSONL和诊断报告保存在本机`logs/`，不随Git分发。基线清单固定部分真机记录摘要；更换配置或模型后不能沿用未知版本前置记录。

软件测试：

```bash
python -m unittest discover -s tests -p 'test_go2*.py'
```

DDS看门狗集成测试会自动启动本地MuJoCo桥接，覆盖单关节控制、偏移保护、第二终端停止、主程序冻结/结束和LowState断流：

```bash
GO2_DDS_TESTS=1 python -m unittest discover -s tests -p test_go2_watchdog.py -v
```
